# FEAT-013 — GOVERNED-EXECUTION-DRIVER

Status: declared feature dossier (Inc-9 health-resolution, decision-level register).

This feature registers **GOVERNED-EXECUTION-DRIVER** in the Coherence / pi-agent-factory feature set. It covers the host-neutral governed execution transport, Hermes Kanban materialization, independent review/fix cycles, goal-loop stages, and backend-gated finalization.


## Design boundary

The Coherence Run is canonical. Before workers start, Coherence compiles an immutable
execution contract and workflow-specific GatePlan. The transport materializes one Kanban
root record plus stage cards when Hermes Kanban is selected; each card carries the run ID,
contract hash, workflow version, stage ID, and attempt. Kanban owns durable operational
lifecycle, dispatch, workspaces, heartbeats, retries, and handoffs. Coherence owns contract
verification, gate evaluation, evidence, traceability, human decisions, and final status.

FEAT-013 does not build a second scheduler, worker supervisor, retry engine, worktree
allocator, or acceptance authority. Hermes is the first durable worker transport. Pi and
Claude Code can execute the same governed run through direct transports without Hermes.

An implementation stage is followed by fresh independent review stages, fixer stages, and
re-review until the workflow's review conditions are satisfied. Hermes goal-mode may provide
continuation and an agentic evaluator inside a bounded stage, but it cannot close the
Coherence Run or alter its GatePlan. Other hosts may implement the same GoalSpec through
their own transport.

Agents may propose or create project-local gates only through the gate-onboarding path.
New gate amendments are queued for a later run; they do not mutate an active contract. A
direct contract/gate modification pauses the run and creates a control-plane finding.
