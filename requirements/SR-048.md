**AC-2 and AC-3 were narrowed during authoring consent (2026-09-03).** AC-2
originally also claimed `required_ci_commands()` raises when "the project
compiles no blocking `ci_verification` obligation" at all. Dropped, not kept
as drafted: `compile_obligations` (`src/coherence/policy/compiler.py`)
unconditionally appends exactly one `ci_verification` obligation for every
scope, so that branch of `required_ci_commands`'s guard (`if not selected:
raise ...`) is unreachable through any real compilation path, and no
currently-passing test exercises it -- both candidate error tests instead hit
the "obligation exists but its `resolve_cmd` is missing" branch, which is
what the narrowed criterion now says. AC-3 originally also claimed the
compiled set holds "exactly one" `ci_verification` obligation. Dropped: the
candidate tests resolve it with `next(o for o in obligations if o.kind ==
"ci_verification")`, which would still pass even if a second one existed, so
no test actually pins that cardinality. The compiler's structure does
guarantee it by construction for project scope, but nothing here tests it, so
the criterion no longer claims it. `required_ci_commands()`
(`src/coherence/policy/ci.py`) and `_ci_verification_obligation()`
(`src/coherence/policy/compiler.py`) implement the behaviour that survived.
