## AC-3 scope note

AC-3 originally claimed both halves of "requirement coverage computes import
overlap for every language the code index parses": (1) a non-Python
selection or changed file must never be silently read as a verified
zero-overlap, and (2) a genuine transitive-overlap answer must actually be
produced for those languages. Only (1) is automatable today; (2) needs real
per-language import-edge extraction (`node_modules`/`tsconfig` resolution for
JS/TS, Cargo for Rust, Go modules, Java classpath, C/C++ includes, Ruby
`require` paths, PHP autoloading, Bash `source`) which is substantial,
multi-week work and stays out of scope here -- the same split SR-001's AC-3
used (see that file's own scope note for the pattern this imitates).

The criterion was narrowed to (1) and bound to a real test: `compute_overlap`
now reports `status="unsupported"` with a named diagnostic (mirroring
`build_import_closure`'s existing suffix check) whenever the selection or a
changed file has a non-Python extension the code index parses as code
(`substrate.codemap.build._CODE_EXTS`, minus `.py`/`.pyi`), and
`coherence.audit.audit.classify()` surfaces a distinct note for that case
instead of the generic "test does not reach changed files" wording. A
non-code changed file (docs, config) is unaffected -- only extensions the
index itself treats as code trigger the signal, so this can never regress
into flagging ordinary non-code changes as "unsupported".

(2) -- producing a real overlap answer per non-Python language -- would need
its own future requirement once that import-edge work exists; SR-004's scope
stays at "never silently wrong," matching what is automatable now.
