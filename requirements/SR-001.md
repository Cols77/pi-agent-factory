The implementation and validation relation contract is detailed in [[docs/superpowers/specs/2026-08-31-sr-code-validation-traceability-design#canonical-relations|SR code and validation traceability design — canonical relations]].

**AC-3 was narrowed during authoring consent (2026-09-02).** It originally also claimed the
reverse direction — "no wikilink in the body names a relation the typed fields do not declare" —
as a `manual` criterion. Dropped, not kept manual: the schema has exactly one typed relation field
(`upstream`), and requirement bodies routinely and legitimately wikilink other nodes for narrative
context that is not an upstream dependency (see [[SR-050]]'s own body, linking [[SR-001]] and
[[SR-023]] in prose with `upstream: []`). Enforcing the reverse claim as written would flag that
normal, correct usage. It becomes well-defined once a broader typed-relation vocabulary exists
(`relates_to`, `distinguished_from`, …) — that vocabulary is [[SR-057]]'s territory, not this SR's.
`missing_upstream_wikilinks()` (`src/coherence/register/register.py`) implements the forward
direction that survived.

**Correction (2026-09-03):** this note originally cited SR-056 for the broader typed-relation
vocabulary. SR-056 was registered the same day but turned out to be an unrelated capability
([[SR-056]] progressive review-decision presentation); the citation above is corrected to
[[SR-057]], the requirement actually registered for this vocabulary gap.
