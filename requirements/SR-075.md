Source: [[docs/superpowers/specs/2026-08-22-coherence-progressive-assurance-design.md#4. Progressive assurance model|Coherence: progressive assurance, obligations and lifecycle traceability]], the "Suspect relationships" bullet: *"This extends the existing freshness/gap machinery — it is not a second dependency graph."*

> Status: proposed; semantic adoption remains subject to the existing per-SR human consent workflow.

Authored 2026-09-17 with project-owner consent given in an interactive session, from the
optional-contract-artifacts plan. "Compile" here means parse, validate, normalize, resolve safe
local relationships and hash. It explicitly does not mean code generation, network retrieval,
shelling out to an external validator, or materializing a second authoritative artifact: the
first increment is read-only and in-memory. Content fingerprints reuse the existing freshness
hashing conventions, so no second content-hash algorithm is introduced. Semantic schema
validation stays out of the compiler — the compiler reports syntax and reference closure, and
project gates and declared consumer tests remain responsible for domain semantics.
