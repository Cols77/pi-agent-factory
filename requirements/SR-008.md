**Statement corrected during authoring consent (2026-09-03).** The statement originally claimed
the system "compile[s] obligations from a seven-dimension profile with fixed enums" -- the design
doc's section-4 vocabulary (`maturity`, `consequence`, `reversibility`, `volatility`,
`verification_cost`, `exposure`, `collaboration`). That per-dimension compilation does not exist:
`DIMENSIONS` in `src/substrate/policy/vocabulary.py` is declared but never consumed by any schema,
resolver, or obligation compiler -- no test constrains or compiles a value for any of the seven
dimensions. A companion doc
([[docs/superpowers/specs/2026-08-22-system-traceability-course-overhaul-design#L214|system
traceability course overhaul design]]) independently confirms the seven-dimension profile is
"designed, not shipped." What the shipped code actually does, and what is well-tested, is resolve
a single flat preset name (one of `exploration`/`prototype`/`product`/`high_assurance`, itself a
fixed enum) through explicit scope precedence, rejecting equal-specificity path-override conflicts,
and compiling obligations only for the two presets FEAT-002's D16 scopes in
(`prototype`/`high_assurance`) -- fail-closed on every other preset name or value. The statement
now describes exactly that. The seven-dimension vocabulary stays as an unused, documented-only
constant in `vocabulary.py` unless/until a future SR scopes compiling it -- that is a materially new
design surface (collapsing seven independent per-dimension enums to one of four presets, or
replacing the preset model outright), not a small mechanical addition, and is out of scope here.

**AC-4 was split out of a single combined criterion during authoring consent (2026-09-03).** The
original draft criterion asserted both "unknown preset name -> `InvalidProfileError`" and "known but
uncompiled preset -> `UncompiledPresetError`" as one claim pointing at a single ref file. The two
error paths live in different modules and are proven by tests in different files
(`InvalidProfileError` in `substrate/policy/vocabulary.py`, `UncompiledPresetError`'s raise site in
`coherence/policy/compiler.py`), so the claim is split into AC-4 (the `InvalidProfileError` path,
plus the two types' distinctness) and AC-5 (the `UncompiledPresetError` path), each bound to the
file that actually proves it -- mirroring how [[SR-001]]'s AC-3 was narrowed during its own
authoring consent.

**AC-2 narrowed during human authoring consent (2026-09-03).** The independent review found AC-2's
"feature/bundle" wording implied two separately-tested inheritance scopes when only one exists:
`coherence.trace.model.NodeKind` has no `bundle` entry (only `feat`), so `resolve_profile` only
ever walks a `contains` edge to an owning **feature** node -- a `bundles/*.json` membership file is
never itself a resolvable `scope_ref`. Confirmed during consent that `bundles/*.json` is not dead
code (it is read by `coherence.navigate.vocabulary`/`remediation`/`guide`, feeding the
navigator/console surfaces) -- the fix here is wording-only, narrowing AC-2 to say "feature," not a
code change and not a signal that bundle-membership tracking should be removed.
