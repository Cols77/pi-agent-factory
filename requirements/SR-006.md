Source: docs/superpowers/specs/2026-08-18-coherence-toolset-design.md#10.

**AC-3 was narrowed during authoring consent (2026-09-02).** It originally claimed universal gating -- "fails the gate under every profile, not only under high_assurance" -- as a `manual` criterion. Dropped, not kept manual: the compiler (`src/coherence/policy/compiler.py`, `_test_marker_obligation`) graduates `test_marker` requiredness by profile -- `blocking` only under `high_assurance`, `required` (-> WARNING, non-gating) otherwise -- the same pattern used for the sibling obligations `task_justification`, `verification_result`, and `human_review` in the same file. This is deliberate, repo-wide policy, not an oversight, so the universal claim is false about the system as designed rather than a gap awaiting a small fix. The true, profile-dependent claim -- that non-`high_assurance` profiles produce a visible, non-gating WARNING rather than silence or an unintended full block -- is real and automatable; it survives as the narrowed AC-3, bound to `test_a_bound_sr_without_the_marker_is_required_under_the_default_profile` in `tests/unit/coherence/test_register_markers.py` (already written; only the `@pytest.mark.sr("SR-006")` marker was missing). Making the original universal claim literally true would require a deliberate policy redesign -- dropping or overriding profile-graduation specifically for `test_marker` while every sibling obligation keeps it -- a product/architecture decision that belongs in a future SR, not this one.
