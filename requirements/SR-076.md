Source: [[docs/superpowers/specs/2026-08-22-coherence-progressive-assurance-design.md#6. Health as a vector|Coherence: progressive assurance, obligations and lifecycle traceability]], the "Health as a vector" section.

> Status: proposed; semantic adoption remains subject to the existing per-SR human consent workflow.

Authored 2026-09-17 with project-owner consent given in an interactive session, from the
optional-contract-artifacts plan. Contract state surfaces through the existing command groups —
`trace check`, `navigate health`, `navigate freshness`, bundle/membership checks and JSON status
projections — rather than through a new top-level CLI group. `contract:<id>` is an additive
bundle member kind, and existing member kinds and JSON outputs stay backward-compatible.
Compiler relationships materialize as ordinary freshness dependency edges consumed by the
existing impact computation and reconciliation policy, so this requirement adds no evidence
record format and no parallel staleness subsystem. Validation of a contract remains an executed
gate or evidence assertion: the compiler stating that a closure resolves is never by itself a
claim that a consumer contract is validated.
