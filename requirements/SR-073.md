Source: [[docs/superpowers/specs/2026-08-18-coherence-toolset-design.md#10. Artifact families currently uncovered|Coherence: a named tool set for continuous system understanding]], the "Artifact families currently uncovered" section.

> Status: proposed; semantic adoption remains subject to the existing per-SR human consent workflow.

Authored 2026-09-17 with project-owner consent given in an interactive session, from the
optional-contract-artifacts plan. Contract artifacts — local JSON Schemas, fixtures, templates,
DDL manifests and protocol descriptions — are the hole §10 names: they are critical interfaces
whose drift a prose-spec/plan trace cannot see today. This requirement makes the catalog the
project's own inventory of exactly which artifacts it claims, so no generic scan of JSON files
is permitted and no project gains contract findings it did not opt into. The catalog carries
identity, relationships and status only; each contract file remains authoritative for its own
semantics, so this requirement must not become a second copy of contract content.
