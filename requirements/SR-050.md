Source: [[docs/superpowers/specs/2026-08-31-sr-code-validation-traceability-design#canonical-relations|SR code and validation traceability design — canonical relations]].

This SR is distinct from [[SR-001]]: SR-001 requires lifecycle navigation; this SR requires
implementation-time maintenance and independent per-SR review of the production and validation
relations that make that navigation truthful. It complements [[SR-023]], which computes
import-overlap coverage, and [[SR-049]], which enforces produced-code traceability through gates.

**AC-1 became `test_marker`-backed (2026-09-03).** `coherence.register.relations.resolve_sr_relations`
now resolves the structured `implemented_by`/`verified_by` relations this design names
(`path`/`symbol`/`test` entries) against the real repository: paths are root-confined with the
same `candidate.is_absolute() or ".." in candidate.parts` convention already used by
`coherence.navigate.snapshots` and `coherence.policy.compiler`, and symbol/pytest-node identifiers
are resolved against the existing code map (`substrate.codemap.store.ensure_fresh` +
`substrate.codemap.build.file_signatures`) rather than a second parser -- no line number is ever
accepted as identity, and a repeated `(field, path, symbol-or-test)` declaration is rejected as a
duplicate rather than silently accepted twice. `coherence.trace.model.edges_from_frontmatter` now
tells the two `verified_by` shapes (this structured relation vs. the pre-existing string-list
SR-to-task/run graph edge) apart by each entry's own shape rather than by node kind, so the legacy
edge keeps working on SR nodes that still use it. `tests/unit/coherence/register/test_relations.py`
binds this AC via `@pytest.mark.sr("SR-050")`.

This landed via a background workflow whose own review stage produced a false "rejected" verdict
— it reported no implementation existed anywhere, based on an investigation that only checked
`git diff` (which does not show untracked new files) and appears to have run against a stale or
mid-write state after a network failure. Independently re-verified from scratch before trusting
either side: read every file directly, confirmed the resolver reuses the code map, confirmed the
`verified_by` fix uses per-entry shape detection (not the node-kind gate the review claimed), and
reran every test myself. One real gap the review did *not* correctly identify but existed
nonetheless — duplicate-relation detection, required by this AC's own source plan — was found by
reading the code directly and fixed the same way (TDD, tests added first).

**AC-3 was narrowed on review (2026-09-02).** It originally named a specific, not-yet-existing
actor — "an agent's relation-review verdict" — as the thing being gated. That producer does not
exist: AC-1 and AC-2 (the structural/fidelity reviewer that would emit such a verdict) remain
`manual` because no reviewer exists in `src/coherence` today. What the AC's substance actually
requires — a gate that only closes on an attributed, correctly-scoped human `accept` decision,
fail-closed on everything else (missing, mis-scoped, unattributed, rejected, or deferred) — is
exactly what `_human_review_obligation` (`src/coherence/policy/compiler.py`) already implements
and what `tests/unit/coherence/policy/test_compiler.py` already exercises exhaustively (missing
decision, wrong-SR scope, wrong `gate_id`, reject, defer, blank/whitespace `decided_by`). AC-3 now
binds to that existing, already-tested mechanism via `@pytest.mark.sr("SR-050")` on six of those
tests. Once AC-1/AC-2's reviewer is built, it must route its verdict through this same
`review:<sr_id>` gate rather than a parallel closure path — that wiring is future work, tracked by
AC-1/AC-2 staying manual.

**AC-2 split into AC-2/AC-4 on review (2026-09-03).** The source design (§ Review agents) names
three distinct reviewers, not two: a **structural trace reviewer** and an **evidence
reconciliation reviewer**, both fully deterministic (relation syntax, path/symbol/test-node
resolution, duplicate declarations, manifest/validation-output reconciliation — graph and file
facts, no judgement involved), and a **fidelity reviewer**, which is not (it judges whether a
link genuinely substantiates a claim). The original AC-2 merged all three into one criterion and
justified all of it as `manual` for the same reason — that reading did not distinguish "manual
because unbuilt, becomes a bare test the moment it exists" (structural, evidence integrity) from
"manual because it is inherently a judgement call, and always will need one" (fidelity). Splitting
makes each criterion's verification story honest: AC-2 now covers only the two deterministic
reviewers and states plainly it needs zero agent or human judgement once built; AC-4 covers only
fidelity, is explicit that the *judgement* stays a model/human call by nature, and ties its
*enforcement* to AC-3's already-built, already-tested gate rather than inventing a second,
parallel closure path — the same "agent proposes, gate enforces attributed human consent, nothing
closes silently" pattern AC-3 already proves works. This also answers a related, corpus-wide
finding raised at the same time: `_human_review_obligation`'s compiled requiredness is
`not_applicable` outside `high_assurance` (`src/coherence/policy/compiler.py`), so under this
repo's own default profile a `manual` criterion's human review is not merely easy to skip — the
system does not require it at all. That gap is not specific to SR-050 or to AC-4; it is tracked as
its own requirement, [[SR-059]], rather than patched here.

**AC-2 became `test_marker`-backed (2026-09-03).** `coherence.register.review` now implements
both deterministic reviewers the source design names (§ Review agents) and the AC-2 split above
scoped to: a **structural trace reviewer**, `structural_review(root, req) -> StructuralReview`,
which reuses `coherence.register.relations.resolve_sr_relations` (AC-1's own resolver) for
malformed/out_of_scope/dangling/duplicate findings and adds the one category that resolver does
not cover — a bound SR declaring zero `implemented_by` or zero `verified_by` entries is `missing`
— plus a register-wide `unaccounted_changed_files(root, reqs, manifests)` for changed files (read
from every evidence run manifest's `implementation.changed_files`, never `git diff`/`git log`,
per the source plan's own instruction) that no SR anywhere declares a relation to; and an
**evidence reconciliation reviewer**, `evidence_reconciliation_review(root, req, manifests) ->
ReconciliationReview`, which partitions declared-vs-changed and declared-vs-executed facts into
exactly the six categories the design names (`declared_and_changed`, `declared_but_not_changed`,
`changed_but_undeclared`, `declared_and_executed`, `executed_but_unlinked`,
`linked_but_stale_or_failed`), with every operational definition — what "executed" and "stale or
failed" mean, and the judgement call of scoping "changed" to manifests that carry a validation
entry for the SR rather than the whole evidence store — spelled out in the module's own
docstrings. `StructuralReview` and `ReconciliationReview` are two structurally separate
dataclasses, never one merged verdict, satisfying AC-2's own "never merged into one verdict"
clause; `coherence register review <SR-ID>|--all` (`src/coherence/register/cli.py`) prints them
as two distinct top-level JSON keys, `structural` and `evidence_reconciliation`. Neither reviewer
touches `src/coherence/policy/compiler.py`'s obligation system or gates anything — both are
read-only reporting, exactly as the source plan's T4 work package requires ("Register it as a
blocking governed obligation" is a later, separate work package, T7); the fidelity reviewer that
AC-4 names remains unbuilt and `manual`, unaffected by this change.
`tests/unit/coherence/register/test_review.py` binds this AC via `@pytest.mark.sr("SR-050")`, with
one fixture per finding class
for both reviewers, including the plan's own explicit fixtures — a changed file with no SR link
anywhere (`unaccounted`) and a `verified_by` link to a deleted test node (`dangling`) — plus a
CLI-level test that a single dangling relation surfaces on the structural side only, never folded
into the evidence-reconciliation output.
