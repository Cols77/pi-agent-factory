---
id: SR-050
title: "Per-requirement implementation traceability review"
statement: "The system shall require each implementation slice to maintain canonical SR relations to the production symbols and validation test nodes that implement and verify the changed behavior, mirror those relations as Obsidian wikilinks, and run a read-only per-SR review that separately reports structural coverage, evidence integrity, and semantic fidelity findings, including missing, dangling, weak, and overstated links, without treating an agent verdict as authoritative until the required gate validates it."
domain: behavioral
upstream: []
source: "docs/superpowers/specs/2026-08-31-sr-code-validation-traceability-design.md#canonical-relations"
acceptance:
  - id: AC-1
    criterion: "Each requirement an implementation slice changes carries typed implementation and validation references whose repository-relative paths resolve inside the project and whose symbol or pytest node identifiers resolve to real definitions, with no line number used as identity."
    verification:
      kind: manual
      reason: "No automated check and no implementation: typed implemented_by and verified_by references on a requirement do not exist anywhere in src/. The existing verified_by edge kind links features and plans to tasks and runs, not requirements to production symbols or test nodes, so no test can bind to this sentence. Until a structural trace reviewer exists, a human must open each requirement the slice touched and confirm every declared path resolves inside the repository, every symbol or pytest node id resolves to a real definition, and no reference identifies a target by line number."
  - id: AC-2
    criterion: "The per-requirement review reports structural coverage, evidence integrity and semantic fidelity findings as separate categories, naming missing, dangling, weak and overstated links distinctly rather than merging them into one verdict."
    verification:
      kind: manual
      reason: "No reviewer exists: nothing under src/coherence implements the structural, fidelity or evidence-reconciliation review of the source design, so there is no output for a test to assert on. A human must read the review output produced for the slice and confirm the three categories appear separately and that a missing link is never reported as, or folded into, an overstated one."
  - id: AC-3
    criterion: "An agent's relation-review verdict does not close a requirement until the required gate records a human decision covering that requirement."
    verification:
      kind: manual
      reason: "No automated coverage is possible today: the compiled human_review obligation hard-codes its reviewed field to false, so the obligation can never reach satisfied however the review went, and outside the high_assurance profile its requiredness is not_applicable, so nothing requires the decision at all. A human must confirm that any slice claiming a relation review for a requirement carries a corresponding gate decision authored by a person, and must refuse to treat the agent verdict alone as closure."
---

Source: [[docs/superpowers/specs/2026-08-31-sr-code-validation-traceability-design#canonical-relations|SR code and validation traceability design — canonical relations]].

This SR is distinct from [[SR-001]]: SR-001 requires lifecycle navigation; this SR requires
implementation-time maintenance and independent per-SR review of the production and validation
relations that make that navigation truthful. It complements [[SR-023]], which computes
import-overlap coverage, and [[SR-049]], which enforces produced-code traceability through gates.
