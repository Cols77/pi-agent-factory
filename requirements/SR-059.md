Source: [[docs/superpowers/specs/2026-09-03-manual-criteria-enforcement-seed|Manual criteria must not silently rot — seed]].

Discovered while splitting [[SR-050]]/AC-2 into AC-2 (structural + evidence-integrity, both
deterministic once built) and AC-4 (semantic fidelity, inherently a judgement call): pushing back
on "manual because unimplemented" surfaced that `_human_review_obligation`
(`src/coherence/policy/compiler.py`) compiles requiredness as `"blocking" if profile ==
"high_assurance" else "not_applicable"` — not a softer severity like [[SR-006]]'s accepted
`test_marker` graduation (`blocking`/`WARNING`), but literally not required at all outside
`high_assurance`. Under this repository's own default profile, a `manual` criterion's human review
is not merely easy to forget: nothing in the system asks for it. This is corpus-wide, not specific
to [[SR-050]] — every `manual`-kind acceptance criterion across every registered requirement is
affected identically.

**Acceptance criteria added on review (2026-09-03), same correction as [[SR-057]]/[[SR-058]].** No
longer zero-AC: AC-1/AC-2 state the observable contract (requiredness never silently
`not_applicable`; an accept decision never silently outlives the content it consented to) without
committing to a mechanism. The fix is not "eliminate manual review" — [[SR-050]]/AC-4 stays a
genuine judgement call by nature, however good tooling gets — it is making reliance on
agent-assisted review with human consent as trustworthy and unskippable as a passing automated
check, the way [[SR-050]]/AC-3 already proves is possible for one specific gate. AC-2 is no longer
hypothetical: presenting [[SR-057]] for its own decision demonstrated it directly (see AC-2's
reason). The seed doc records recon toward generalizing that proof: a possible new
`verification.kind` in the register schema and a staleness/expiry contract for review decisions —
not committed here.
